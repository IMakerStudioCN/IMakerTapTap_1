# WindowKit 使用手册

> 环境：Unity 2022.3 + QFramework（UIKit / CodeGenKit）
> 能力：**打开/关闭/最小化/恢复、全屏、缩放、拖拽、堆叠（z 序 + 层叠摆放）**
> 定位：像 `UIKit` 一样用 —— `WindowKit.Open("面板名")` 就打开一扇窗，**不需要注册、不需要任何 ScriptableObject**。

---

## 0. 三十秒看懂结构

```
TestWindow                      ← 面板根（UIPanel 壳，名字 = prefab 名 = 打开用的名字；UIKit 管开关，别动它）
└─ Contant
   └─ BasePlate                 ← 窗口根：挂 WindowsBasic，套件所有几何/交互都作用在它身上
      ├─ Bar                    ← 拖拽把手（名字固定 Bar）
      ├─ ContentBox             ← 内容区：你写业务 UI 的地方（代码里就是 WindowsBasic.Content）
      │   └─ ...你的内容...
      ├─ Exit / Mini / Full     ← 关闭 / 最小化 / 全屏开关（名字固定）
      └─ ...
```

| 层 | 谁 | 管什么 |
|---|---|---|
| 套件入口 | `WindowKit`（静态） | 谁打开、谁在上、层叠摆放、事件 |
| 窗口壳 | `WindowsBasic`（挂窗口根） | 全屏/拖拽/缩放/位置记忆/关窗最小化/内容裁剪 |
| 你的逻辑 | `XxxWindow : WindowsBasic`（挂窗口根）、`XxxContent : MonoBehaviour`（挂 ContentBox 或内容 prefab） | 只写这块 UI 自己的事 |

**文件地图**

| 文件 | 作用 |
|---|---|
| `Scripts/WindowControl/WindowKit.cs` | 套件入口（静态）：打开/关闭/最小化/全屏/堆叠/事件 |
| `Scripts/WindowControl/WindowsBasic.cs` | 窗口壳组件：几何、交互、状态、`Content`、扩展钩子 |
| `Scripts/WindowControl/WindowsController.cs` | 业务壳脚本样例（`: WindowsBasic`，挂在窗口根） |
| `Scripts/WindowControl/System/WindowsSystem.cs` | 架构门面：`this.GetSystem<IWindowsSystem>()` 用（内部转发 WindowKit） |
| `Scripts/WindowControl/Utility/WindowsUtility.cs` | 纯几何工具：矩形换算、桌面区、缩放、内容自适应 |
| `Art/UIPrefab/WindowKit.prefab` | **窗口模板**：复制它新建窗口 |

## 1. 五分钟跑起来（不写一行代码）

1. 复制 `Art/UIPrefab/WindowKit.prefab` → 改名（例如 `TestWindow.prefab`）；
2. Prefab Mode 里把**根物体名**改成同名，清空 `ContentBox` 换自己的 UI；
3. 给 prefab 标 **AssetBundle**（例如 `testwindow_prefab`）—— ResKit 按资源名加载，不标就找不到；
4. 桌面图标（`SoftwareSingle`）的 `windowName` 填 `TestWindow`；
5. Play → 点图标，窗口就出来了：拖 `Bar`、拉边缩放、双击标题栏/点 `Full` 全屏、`Mini` 最小化、`Exit` 关闭、再点图标原地恢复。

代码里打开也一样：

```csharp
WindowKit.Open("TestWindow");                        // 没开就开；已开则恢复 + 置顶
WindowKit.Open("TestWindow", new Vector2(900, 600)); // 打开并指定尺寸（居中）
WindowKit.Open<TestWindow>();                        // 用类型打开（编译期查错）

WindowKit.ToggleFullScreen("TestWindow");
WindowKit.Minimize("TestWindow");
WindowKit.Restore("TestWindow");
WindowKit.Close("TestWindow");
WindowKit.CloseAll();

WindowKit.Active;                                    // 最上层窗口
WindowKit.IsOpened("TestWindow");
WindowKit.SetWindowSize("TestWindow", new Vector2(800, 600));
WindowKit.CenterWindow("TestWindow");
foreach (var w in WindowKit.Windows) { }             // 底 -> 顶

// 事件（任务栏 / 存档 / 统计）
WindowKit.OnOpened.Register(w => Debug.Log("打开 " + w.WindowName));
WindowKit.OnClosed.Register(w => Debug.Log("关闭 " + w.WindowName));
WindowKit.OnFocused.Register(w => Debug.Log("置顶 " + w.WindowName));
WindowKit.OnStateChanged.Register(w => Debug.Log(w.WindowName + " -> " + w.KitState));
```

## 2. 怎么加脚本

### 2.1 四种脚本挂哪儿（先对号入座）

| 你写的逻辑 | 挂在哪 | 基类/接口 | 入口 |
|---|---|---|---|
| 这扇窗**独有**的行为（读存档、刷新任务栏、初始化内容） | 窗口根 `BasePlate` | `XxxWindow : WindowsBasic` | `OnWindowConfigure / OnWindowReady / OnWindowStateChanged …` |
| 纯 UI 内容（列表、按钮、选项页） | `ContentBox` 或其子物体、内容 prefab 根 | `MonoBehaviour` / `ViewController` | `Awake / Start / OnEnable / 自己的事件` |
| 内容要被**多个窗口复用** | 独立 prefab，运行时挂进 `ContentBox` | `MonoBehaviour` | 对外 `Setup(...)` |
| 从系统层/命令里操作窗口 | 任意 `AbstractCommand` / `AbstractSystem` | `IController` | `this.GetSystem<IWindowsSystem>().OpenWindows(...)` |

### 2.2 模板 A：窗口壳脚本（挂窗口根，`: WindowsBasic`）

```csharp
using UnityEngine;
using QFramework;

namespace TapTapFirst
{
    // 挂在窗口根（BasePlate）。只写这扇窗特有的事，窗口壳能力都从基类继承
    public class TestWindow : WindowsBasic
    {
        [SerializeField] private TestContent content;   // 方式 1：Inspector 拖内容脚本

        protected override void OnWindowConfigure()     // 初始化参数（在摆位之前调用）
        {
            SetInitWindowSize(new Vector2(900, 600), centerOnDesktop: true);
            SetMinSize(new Vector2(320, 240));
        }

        protected override void OnWindowReady()         // 初始化完成（相当于以前的 Start 主体）
        {
            // 方式 2：现场找（内容在 ContentBox 里）
            content = content != null ? content : Content.GetComponentInChildren<TestContent>(true);
            content?.Setup(this);

            // 方式 3：把 ContentBox 里的某个控件交给别的系统
            var refreshButton = WindowsUtility.FindChildByName(Content, "RefreshButton");
        }

        protected override void OnFullScreenChanged(bool isFull) { content?.OnFullScreenChanged(isFull); }
        protected override void OnWindowStateChanged(WindowKitState state) { /* 最小化/全屏变化 */ }
        protected override void OnWindowClose() { /* 关窗前存档 */ }
    }
}
```

**三条硬规则**

1. **不要写 `Awake()` / `Start()`**：Unity 只会调最派生的那个，会把 `WindowsBasic` 的初始化顶掉（表现：按钮没反应、全屏状态不恢复、布局没自适应）。确实要写就 `protected override void Start() { base.Start(); ...; }`。
2. **不要重复声明** `GetArchitecture()` / 自己查 `IWindowsSystem`：基类已经给你 `WinSystem`、`WinUtility`、`WindowName`、`Content`、`State`、`IsFullScreen`、`KitState`。
3. 挂了自己的派生类，**就把模板上那个 `WindowsBasic` 组件移除**（两个一起处理指针会打架）。

### 2.3 模板 B：内容脚本（挂 `ContentBox` 或内容 prefab 根）

```csharp
using UnityEngine;
using UnityEngine.UI;
using UnityEngine.EventSystems;

namespace TapTapFirst
{
    public class TestContent : MonoBehaviour
    {
        [SerializeField] private Button refreshButton;      // Inspector 拖 ContentBox 里的控件
        [SerializeField] private Toggle autoUpdateToggle;

        private WindowsBasic mWindow;

        void Awake()
        {
            refreshButton.onClick.AddListener(OnRefresh);   // 绑自己的控件，随便写
            autoUpdateToggle.onValueChanged.AddListener(OnAutoUpdate);
        }

        void OnDestroy()
        {
            refreshButton.onClick.RemoveListener(OnRefresh);
            autoUpdateToggle.onValueChanged.RemoveListener(OnAutoUpdate);
        }

        // 外部注入（推荐从窗口的 OnWindowReady 里调）
        public void Setup(WindowsBasic window)
        {
            mWindow = window;
            Relayout();
        }

        // 窗口被 Mini 隐藏后再打开会走这里（Start 只跑一次，别把刷新放 Start）
        void OnEnable() => Relayout();

        // 窗口缩放 / 全屏 / 分辨率变化时重新排版（比 Update 轮询省）
        void OnRectTransformDimensionsChange() => Relayout();

        private void OnRefresh()
        {
            mWindow = mWindow != null ? mWindow : GetComponentInParent<WindowsBasic>();
            mWindow?.SetWindowSize(new Vector2(600, 400));   // 需要操作窗口就往上拿
        }

        private void OnAutoUpdate(bool on) { }

        private void Relayout() { /* 只改 ContentBox 的子物体 */ }
    }
}
```

**内容脚本的五条规范**

1. 只改**自己的子物体**：`ContentBox` 自己的锚点由套件接管（启动时 `AutoFit` 成四边拉伸），别去写死它。
2. `ContentSizeFitter` 别挂 `ContentBox` 上（会和自己四边拉伸打架），挂里面那层 `Content`；**窗口根和它的父级**别挂 `LayoutGroup`。
3. 只实现 `IPointerClickHandler` 的组件，**补一个空的 `OnPointerDown`**，否则点击会被窗口根截走：

```csharp
public class Item : MonoBehaviour, IPointerDownHandler, IPointerClickHandler
{
    public void OnPointerDown(PointerEventData e) { }   // 空实现，只为拿到 pointerPress
    public void OnPointerClick(PointerEventData e) { /* 你的逻辑 */ }
}
```

4. 窗口缩小时内容默认会被 `RectMask2D` 裁掉（`autoClipContent`）；想允许溢出就把它关掉，或给内容做成自适应（锚点 / `LayoutGroup` / `ScrollRect`）。
5. 别给内容换父级、也别挪出窗口：套件的几何和堆叠按窗口根算，换父级会乱。

### 2.4 内容脚本挂载规范：内容的管理脚本一律挂在 `ContentBox` 上

**规则**：`ContentBox` 里的 UI（按钮 / 文本 / 列表 / 图片…）**自己不挂脚本**；管理它们的 `MonoBehaviour` **全部挂在 `ContentBox` 这一个节点上**（可以挂多个组件）。

| 位置 | 放什么 |
|---|---|
| `ContentBox` 节点 | **所有内容管理脚本**（绑按钮、刷列表、处理数据、收点击） |
| `ContentBox` 的子物体 | 只放 UI 组件（RectTransform / Image / Text / Button / Toggle …），不放脚本 |
| 运行时 `Instantiate` 的 item prefab | 例外：脚本挂在自己的 item prefab 根上（见下面「例外」） |

**行得通，但有三条前提**

1. **拿引用没问题**：挂在 ContentBox 上的脚本可以 `[SerializeField]` 拖子控件、用 CodeGenKit Bind、`GetComponentInChildren<T>(true)`、或 `WindowsUtility.FindChildByName(Content, "OkButton")`。
2. **别改 ContentBox 自己的锚点/offset**：它由套件的 `AutoFit` 接管（启动时设成四边拉伸）；要布局就改**子物体**。
3. **要收点击，必须同时实现一个空的 `OnPointerDown`**：窗口根实现了 `IPointerDownHandler`，只写 `IPointerClickHandler` 的组件会被窗口根截走（UGUI 规则）。

```csharp
// 挂在 ContentBox 上：一个脚本管所有子控件（连点击一起管）
public class TestContent : MonoBehaviour, IPointerDownHandler, IPointerClickHandler
{
    [SerializeField] private Button okButton;        // Inspector 里从子物体拖进来
    [SerializeField] private Button cancelButton;

    void Awake()
    {
        okButton.onClick.AddListener(() => Debug.Log("OK"));
        cancelButton.onClick.AddListener(() => Debug.Log("Cancel"));
    }

    // 空实现：抢下 pointerPress，OnPointerClick 才会派发到我们身上
    public void OnPointerDown(PointerEventData e) { }

    // 想在 ContentBox 上统一处理「点到了哪个子控件」就用这个
    public void OnPointerClick(PointerEventData e)
    {
        var hit = e.pointerCurrentRaycast.gameObject;     // 真正被点中的物体
        if (hit == null) return;

        if (hit == okButton.gameObject) { /* ... */ }
        // 也可以按名字/组件判断：hit.GetComponentInParent<MapPoint>()
    }
}
```

**好处**：内容只有一个入口，复制模板/换内容时一目了然；不用在几十个子节点里翻脚本；`Mini` 隐藏恢复、`RectMask2D` 裁剪这些套件能力天然覆盖到它。

**代价 / 建议**

- 组件一多（列表 + 分页 + 设置项都塞一个类）会变胖 → 建议：ContentBox 上放 **1 个总控** + 复杂块再拆 1~2 个脚本（仍挂 ContentBox），单一职责的列表项按下面的例外处理。
- 引用多的时候用 CodeGenKit Bind 生成字段，别手写一堆 `Find`。

**两个例外**

| 情况 | 怎么办 |
|---|---|
| 运行时 `Instantiate` 的列表项 / 卡片 | 脚本挂**自己的 item prefab 根**上（ContentBox 上只放总控，负责生成和绑定，见 3.4） |
| 需要**溢出可见**的内容（悬浮提示、下拉菜单超出窗口） | 放到窗口根下单独一层 Overlay，并把窗口的 `autoClipContent` 关掉 |

## 3. 怎么获取 ContentBox 里的 UI

### 3.1 五种方式（按推荐顺序）

| 方式 | 写法 | 适合 |
|---|---|---|
| ① Inspector 拖引用 | `[SerializeField] private Button ok;` | 固定内容，最直观 |
| ② CodeGenKit Bind | 选中节点 → Bind → 重新生成 `Xxx.Designer.cs`，字段自动出现 | 和 `Exit/Mini/Full` 一样的官方流程 |
| ③ 运行时按名字找 | `WindowsUtility.FindChildByName(Content, "OkButton")` | 内容 prefab 不固定、或懒得拖引用 |
| ④ 按组件找 | `Content.GetComponentInChildren<TestContent>(true)` | 找「整块内容」的脚本 |
| ⑤ 事件 / 命令（QFramework） | `this.SendEvent(...)` / `this.SendCommand(...)` | 跨模块解耦（存档、任务栏、系统层） |

```csharp
// ③ 按名字找（递归，名字对就行，不用管层级）
var rt = WindowsUtility.FindChildByName(Content, "OkButton");
var ok = rt != null ? rt.GetComponent<Button>() : null;

// ④ 按组件找（true = 包含隐藏的子物体）
var content = Content.GetComponentInChildren<TestContent>(true);

// 内容脚本对外暴露能力（推荐：外部不碰内部结构）
public class TestContent : MonoBehaviour
{
    public event System.Action<string> OnItemSelected;
    public void Setup(WindowsBasic window) { }
    public void SelectFirst() { }
}
```

### 3.2 从外部：打开窗口 → 拿内容 → 传数据

```csharp
var win = WindowKit.Open("TestWindow");          // 打开（或恢复+置顶）
if (win != null)
{
    win.SetWindowSize(new Vector2(900, 600));     // 顺手改尺寸

    var content = win.Content.GetComponentInChildren<TestContent>(true);
    content?.Setup(win);                         // 把窗口/数据交给内容
    content?.SelectFirst();
}

// 只想拿已打开的窗口（不想打开）
var opened = WindowKit.Get("TestWindow");
opened?.Content.GetComponentInChildren<TestContent>(true)?.SelectFirst();
```

> 提示：`WindowKit.Open` 返回的是**窗口组件**；面板实例化那一刻它的 `Start` 还没跑，所以返回非 null 不代表内容已经初始化完。
> 想要「打开后一定能拿到初始化好的内容」，用下面两种之一：

| 做法 | 写法 |
|---|---|
| 内容自己拉数据 | 内容脚本在 `Awake/OnEnable` 里从系统/存档取数据（不依赖外部注入） |
| 窗口注入（推荐） | 窗口壳脚本的 `OnWindowReady()` 里把数据/自己交给内容（见 2.2） |

### 3.3 内容 → 窗口 / 内容 → 外部

```csharp
// 内容里要操作窗口：往上拿
var win = GetComponentInParent<WindowsBasic>();
win?.SetFullScreen(true);
win?.MinimizeWindow();
win?.CloseWindow();
win?.SetWindowSize(new Vector2(600, 400));
win?.WindowName;   // 窗口名
win?.KitState;     // Normal / Minimized / FullScreen

// 内容要通知外部（任务栏、系统层）：发事件 / 命令
this.SendEvent(new WindowContentClickedEvent { windowName = win != null ? win.WindowName : null });

// 外部要监听窗口生命周期：用套件事件
WindowKit.OnOpened.Register(w => Debug.Log("打开 " + w.WindowName));
WindowKit.OnStateChanged.Register(w => Debug.Log(w.WindowName + " -> " + w.KitState));
```

> 内容脚本要能发事件，就要实现 `IController`（`public IArchitecture GetArchitecture() => TapTap.Interface;`）；不想实现就只用 `GetComponentInParent<WindowsBasic>()` 这条线。

### 3.4 复用内容 prefab（运行时挂进 ContentBox）

```csharp
public class TestWindow : WindowsBasic
{
    [SerializeField] private GameObject contentPrefab;   // Art/UIPrefab/TestContent.prefab

    protected override void OnWindowReady()
    {
        var go = Instantiate(contentPrefab, Content, false);
        WindowsUtility.StretchBox((RectTransform)go.transform);                    // 铺满
        // WindowsUtility.StretchBox((RectTransform)go.transform, 12, 12, 12, 12);  // 留 12px 边距

        go.GetComponent<TestContent>()?.Setup(this);
    }
}
```

复用内容的注意点：内容 prefab 里**别写死绝对位置**（用锚点 / `LayoutGroup`）；内容脚本不要依赖某个具体窗口类，只依赖 `WindowsBasic` 或你自己定义的接口。

## 4. API 速查

### 4.1 WindowKit（静态入口）

**全局参数**：`CascadeOnOpen`(true) / `CascadeOffset`((32,-32)) / `CascadeSteps`(8)

| 分类 | 方法 |
|---|---|
| 打开 | `Open(name, level)`、`Open(name, size, center, level)`、`Open<T>(level)`、`Open<T>(size, center, level)`、`OpenPanel(name, level)`、`OpenPanel<T>(level)`、`Restore(name)` |
| 关闭 | `Close(name)`、`CloseAll()`、`Minimize(name)` |
| 全屏 | `SetFullScreen(name, bool)`、`ToggleFullScreen(name)` |
| 堆叠 | `Focus(name)` / `Focus(window)`、`CascadeAll()`、`CascadeOffsetAt(index)` |
| 几何 | `SetWindowSize(name, size, keepCenter = true)`、`CenterWindow(name)` |
| 查询 | `Windows`（底→顶）、`Active`（= `Focused`）、`OpenedCount`、`Get(name)`、`IsOpened(name)` |
| 焦点 | `Focused`（当前前台窗口 = 可见的最上层）、`IsFocused(name)` / `IsFocused(window)` |
| 事件 | `OnOpened`、`OnClosed`、`OnFocused`、`OnStateChanged`（`EasyEvent<WindowsBasic>`） |

### 4.2 WindowsBasic（窗口壳组件）

| 分类 | 成员 |
|---|---|
| 读取 | `WindowName`、`State`、`IsFullScreen`、`KitState`、`Frame`（窗口根）、`Content`（= ContentBox） |
| 操作 | `SetFullScreen(bool, bool animate = true)`、`ToggleFullScreen()`、`MinimizeWindow()`、`ShowWindow()`、`CloseWindow()`、`BringToFront()` |
| 几何 | `SetWindowSize(size, keepCenter = true)`、`SetWindowRect(rect)`、`CenterWindow()`、`CascadeTo(index)`、`SetMinSize(size)`、`SetTaskbarHeight(h)` |
| 初始化 | `SetInitWindowSize(size, centerOnDesktop = true, offset = default)`、`InitWindow()`（幂等） |
| 钩子（可重写） | `OnWindowConfigure`、`OnWindowReady`、`OnWindowFocused`、`OnWindowFocusChanged(bool)`、`OnWindowStateChanged(WindowKitState)`、`OnWindowClose`、`OnWindowMinimize`、`OnFullScreenChanged(bool)`、`ResolveWindowName()` |
| 受保护可用 | `WinSystem`、`WinUtility` |

### 4.3 Inspector 参数（窗口根上的 WindowsBasic）

| 分组 | 字段 | 默认 | 说明 |
|---|---|---|---|
| 标识 | `panelName` | 空 | 留空 = 自动用面板根（UIPanel）名字 |
| 节点 | `frame` / `dragHandle` / `contentBox` / `closeButton` / `miniButton` / `fullScreenToggle` | 空 | 留空 = 自动找 `Bar` / `ContentBox` / `Exit` / `Mini` / `Full`（递归同名子物体） |
| 初始窗口 | `initWindowSize` / `initCenterOnDesktop` / `initWindowOffset` / `startFullScreen` | (0,0) / true / (0,0) / false | 尺寸填 0 = 用 prefab 里摆的尺寸；`startFullScreen` = 打开就全屏 |
| 几何 | `taskbarHeight` / `minSize` / `duration` | 50 / 240×160 / 0.18 | 全屏让出任务栏高度 / 最小尺寸（会自动抬高到装得下标题栏按钮） / 全屏动画时长 |
| 几何 | `autoAdaptLayout` / `rememberAcrossClose` / `autoCreateRaycastTarget` / `autoClipContent` | 全 true | 启动自动适配布局 / 记住位置与全屏 / 自动补点击层 / 内容区自动加 `RectMask2D` |
| 交互 | `enableDrag` / `enableResize` / `resizeBorder` | true / true / 6 | 可否拖拽 / 可否缩放 / 边缘命中宽度(px) |
| 交互 | `bringToFrontOnPointerDown` / `doubleClickTitleBarTogglesFullScreen` / `dragFromFullScreenRestores` | 全 true | 按下置顶 / 双击标题栏切全屏 / 全屏时拖动先还原 |
| 光标 | `showResizeCursor` / `cursorHorizontal` / `cursorVertical` / `cursorTopLeftBottomRight` / `cursorTopRightBottomLeft` / `cursorHotspot` / `cursorMode` | 关 / 空 ×4 / (16,16) / Auto | 悬停或拖动边缘时切换鼠标形状（默认关闭，见 5.6） |

### 4.4 WindowsSystem（架构门面，可选）

`TapTap.cs` 已注册，想在 `AbstractCommand` / `AbstractSystem` / `AbstractModel` 里用：

```csharp
var windows = this.GetSystem<IWindowsSystem>();
windows.OpenWindows("TestWindow");
windows.FocusWindows("TestWindow");
windows.MinimizeWindows("TestWindow");
windows.RestoreWindows("TestWindow");
windows.ToggleFullScreenWindows("TestWindow");
windows.SetFullScreen("TestWindow", true);
windows.CloseWindows("TestWindow");
windows.CloseAllWindows();
windows.IsOpened("TestWindow");
```

MonoBehaviour 不用绕这一层，直接 `WindowKit.xxx(...)` 更短。

## 5. 交互规则（知道这些就不会互相打架）

### 5.1 全屏

- 目标矩形 = 面板根矩形 − `taskbarHeight`（默认 50，让出底部任务栏）；想盖住任务栏就填 0。
- 0.18s 平滑动画（`duration`），动画互斥；切全屏会自动置顶并写入位置记忆。
- 还原位置 = 进全屏前记下的窗口矩形，夹回桌面区且不小于 `minSize`。
- `dragFromFullScreenRestores`（默认开）：全屏时按住标题栏拖动会先还原成窗口态再跟手。

### 5.2 缩放

- 命中区 = 窗口根边缘 `resizeBorder`（默认 6px）以内；四个角同时命中两条边 = 对角缩放。
- 只动被拖的边、不低于 `minSize`、不超出桌面区；全屏时不响应；`enableResize = false` 可整体关掉。

### 5.3 拖拽

- 只有按在 `Bar`（`dragHandle`）及其子物体上才拖动窗口，点内容不会误拖。
- 拖动结束写回 `State.WindowedRect`，全屏还原时回到用户摆的位置。
- 双击 `Bar` 切全屏；拖动/缩放开始时会自动取消在飞的全屏动画。

### 5.4 堆叠

- 套件维护一个栈：`WindowKit.Windows`（底→顶），`WindowKit.Active` 是最上层；打开、点窗口、切全屏、`Focus` 都会置顶。
- 关闭 / 最小化一扇窗后，自动聚焦栈里下一个仍可见的窗口。
- `CascadeOnOpen = true`（默认）：新窗口在桌面区居中 + 按打开顺序错开 `CascadeOffset`，超过 `CascadeSteps` 回起点；`CascadeAll()` 一键重排。

**焦点（谁在前台）**

```csharp
WindowKit.Focused;                       // 当前前台窗口（可见的最上层）；没有则 null
WindowKit.IsFocused("TestWindow");       // 某一扇窗是不是前台
WindowKit.IsFocused(window);            // 用组件判断
```

- 打开窗口、点窗口任意位置、切全屏、`WindowKit.Focus(...)` 都会让它成为前台；**上一个前台窗口会收到失焦通知**。
- `Mini` 最小化 / `Exit` 关闭 / 被别的窗口顶下去 → 失焦；套件会把焦点交给下一个可见窗口。
- 隐藏（最小化）的窗口**永远不会**是 `Focused`。
- 窗口自己在 `protected override void OnWindowFocusChanged(bool focused)` 里收通知（`OnWindowFocused()` 只在拿到焦点时触发）。

### 5.5 点击谁优先

- `Button` / `Toggle` / `Slider` / `TMP_InputField` 这些 `Selectable` 派生控件自己吃掉点击，不会被窗口根截走。
- 自己写的组件**只**实现 `IPointerClickHandler` 时必须补一个空的 `OnPointerDown`（见 2.3）。
- 拉边缩放靠窗口边缘那一圈（内容区离边 10/20/10/30），点内容不会被判成缩放。

---

### 5.6 光标（可选）

默认**关闭**（不影响现有观感）。想要「拉边时变成拉伸光标」，在窗口根的 WindowsBasic 上勾 `showResizeCursor`，再把 4 张贴图拖上：

| 字段 | 对应方向 |
|---|---|
| `cursorHorizontal` | ↔ 左右拉（命中 Left / Right） |
| `cursorVertical` | ↕ 上下拉（命中 Top / Bottom） |
| `cursorTopLeftBottomRight` | ＼ 对角（左上角 / 右下角） |
| `cursorTopRightBottomLeft` | ／ 对角（右上角 / 左下角） |

- `cursorHotspot`：热点，默认 `(16,16)`（32×32 的图一般就是中心）
- `cursorMode`：`Auto`（默认，用硬件光标）或 `ForceSoftware`（自定义图不生效时改它）
- 行为：鼠标进到窗口边缘 `resizeBorder`（6px）内就换光标；**按下开始拉边后锁定**该光标（拖出边缘也不乱闪）；松开、鼠标离开窗口、`Mini` 隐藏、关闭窗口都会恢复默认
- 全屏状态不切光标（全屏本来就不能缩放）
- **平台限制**：`Cursor.SetCursor` 在 WebGL / 移动端不生效（那时得用一张跟随鼠标的 `Image` 自己画）；贴图建议 32×32，Texture Type 选 `Cursor` 也行、不选也能用

## 6. 新建一个窗口（5 步）

1. 复制 `Art/UIPrefab/WindowKit.prefab` → 改名（例如 `TestWindow.prefab`）。
2. Prefab Mode：把**根物体名**改成同名；或不动根名，在窗口根 WindowsBasic 里填 `panelName`。
3. 清空 / 替换 `ContentBox` 里的内容，放自己的 UI（见 2.3 / 3.x）。
4. 给 prefab 标 **AssetBundle**（例如 `testwindow_prefab`）—— ResKit 按资源名加载，不标就 `Failed to Create Res`。
5. 打开方式任选：图标上填 `windowName`；或代码 `WindowKit.Open("TestWindow")`。要开局全屏就勾 `startFullScreen`。

**名字链**：prefab 文件名 = 根物体名（或 `panelName`）= 打开时用的字符串。

**自定义初始化（窗口大小等）三种写法**

```csharp
// ① 零代码：Inspector 填 initWindowSize / initCenterOnDesktop / initWindowOffset / minSize / taskbarHeight / startFullScreen

// ② 派生类：OnWindowConfigure 里设
protected override void OnWindowConfigure()
{
    SetInitWindowSize(new Vector2(900, 600), centerOnDesktop: true);
    SetMinSize(new Vector2(320, 240));
}

// ③ 外部随时改
WindowKit.Open("TestWindow", new Vector2(900, 600));
WindowKit.SetWindowSize("TestWindow", new Vector2(600, 400));

var win = WindowKit.Get("TestWindow");
win?.SetWindowSize(new Vector2(600, 400));
win?.CenterWindow();
```

## 7. 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 按钮点了没反应 / 全屏状态不恢复 / 布局没自适应 | 派生类里写了 `void Start()` / `void Awake()`，把基类的顶掉了 | 删掉它们，或 `protected override void Start() { base.Start(); ... }` |
| 点图标没反应 | 图标 `windowName` 为空 / 名字链对不上 / prefab 没标 AB | 填 `windowName`；统一三处名字；标 `assetBundleName` |
| 隐藏（`Mini`）后点图标打不开 | 历史 bug：隐藏是 UIKit 关掉**面板根**，只看 `activeSelf` 会误判为「本来就可见」 | 已修复（改用 `activeInHierarchy`，并保留 `mPanel.Show → UIKit.ShowPanel → UIKit.OpenPanel` 三级兜底） |
| `Mini` / `Exit` 点了没反应 | 历史 bug：窗口名在 `Awake` 时取到 `Xxx(Clone)`，按名字查不到面板 | 已修复（名字改在 `InitWindow` 解析 + 去掉 `(Clone)`；关闭/隐藏优先用面板实例） |
| Console 警告「不是通过 UIKit 打开的面板」 | 场景里手摆了一份窗口副本，同名会和图标开出来的面板打架 | 删掉场景里那份副本（正式窗口只由 `WindowKit.Open` 产生） |
| 缩到很小后内容溢出到窗口外 | 内容固定尺寸又没遮罩 | 默认已自动加 `RectMask2D`（`autoClipContent`）；或把内容做成自适应 |
| `NullReferenceException at ...NewState()` | 走了 `this.GetUtility<IWindowsUtility>()` 但没注册 | `TapTap.Init` 里 `RegisterUtility<IWindowsUtility>(new WindowsUtility())`，或直接用静态 API |
| 拖不动 | 没找到 `Bar` / `enableDrag` 关了 / 被别的透明 Image 挡住 | 改名或手动拖 `dragHandle`；把遮挡层的 Raycast Target 关掉 |
| 拉边缘没反应 | 不在 6px 内 / `enableResize` 关了 / 正在全屏 | 调大 `resizeBorder`；先还原再缩放 |
| 窗口总出现在同一位置 | `CascadeOnOpen = false` 且 prefab 位置相同，或存在位置记忆 | 打开层叠；或换窗口名 / 关掉 `rememberAcrossClose` |
| 关窗后别的窗口没浮上来 | 那扇窗没挂 `WindowsBasic`（没注册进套件） | 确认窗口根挂了 WindowsBasic |

## 8. 已知限制 / 后续可做

- 位置记忆只在**同一次运行内**有效（套件静态字典按窗口名缓存）；跨启动存档自己接 `JsonSaveUtility`。
- 没有窗口吸附（边缘/窗口间对齐）和 Aero Snap（拖到顶部最大化）。
- 光标反馈需要自备贴图：默认关闭，勾 `showResizeCursor` + 拖 4 张贴图即可（见 5.6）；WebGL / 移动端 `Cursor.SetCursor` 不生效。
- 任务栏还没接：`Taskbar.cs` 里订阅 `WindowKit.OnOpened / OnClosed / OnFocused / OnStateChanged` 即可。
- 多显示器 / 安全区（刘海屏）没处理，需要时改 `WindowsUtility.GetDesktopRect` 的数据源。
